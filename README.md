# FloatTranslate Next

基于 [CH-DONG77/FloatTranslate](https://github.com/CH-DONG77/FloatTranslate) 的本地二次开发版本。上游参考分支 `panel`，提交 `1b521d19257dd592e1ebf8c9bbac0961ce3000cc`。保留上游 MIT 许可证；本版本改用 Qt/PySide6，重新实现覆盖界面与平台适配。

## 0.3.9 macOS 27 OCR 兼容性

- 修复 macOS 27.0.1 上 Vision 初始化报 `NSInvalidArgumentException - key does not exist`：使用原生字典和 CGImage 图像输入。
- 高精度引擎出现 `CRImageReaderError` 等错误时自动回退到兼容识别；按源语言记忆成功路径，后续翻译避免反复触发失败引擎。
- 诊断显示实际 OCR 引擎；本机 OCR 错误明确标记，且失败阶段仍记录真实耗时，避免误判为 API Key 无效。
- 增加首次启动自动语言识别、Qt 后台线程、macOS 14 / 26 / 27.0.1 的原生识别回归。

## macOS 测试包构建

GitHub Actions 在 `macos-15`（Apple 芯片 arm64）与 `macos-15-intel`（Intel x64）分别构建。打开仓库 Actions → Test and package desktop app → 成功的运行，在 Artifacts 下载对应架构，内含 `.app.zip`、`.dmg` 和 SHA-256。安装和权限详见 [MACOS.md](MACOS.md)。构建完成不代表桌面权限、多屏和全局快捷键已通过用户实机验收。

## 0.3.8 关于与 GitHub 更新

- 右键“关于 / 检查更新”查看版本、系统、许可证、原项目来源，并配置独立的更新仓库。
- 可在启动后每天检查一次更高稳定版本；支持后台下载、进度、SHA-256 校验、Windows EXE 升级并重启。新版本通过 Qt 启动检查后才退出旧程序，替换时保留备份。
- 更新源需要完整 `用户名/仓库名`；须发布本软件专用清单及对应平台附件，避免误安装原项目的其他程序。详见 [UPDATES.md](UPDATES.md)。
- macOS / 源码运行可检查更新，安装通过发布页手动完成；macOS 尚未实机验收。

## 0.3.7 触底向上拉伸

- 修复仅区分左右、始终从底角缩放的问题。向上避让展开时，触点改为左上 / 右上，拖动固定下边界，支持继续向上增高。
- 拖拽期间保持同一角点，防止手势中途跳角；向下拉伸抵达工作区底边后，松开即切换到上角，下一次可向上拉伸。
- 四个方向均固定相对的两条边与书签位置，边界限制以屏幕可用工作区（排除任务栏）为准；尺寸会在收起后再次展开保留。
- 自动翻译关闭时，缩放仍不触发识别或 API 请求。原生自检验证四角的 Windows 原生命中、宽高增长、对边与书签固定；另覆盖触底后换角与收起重开。

## 0.3.6 Enter 与全局立即翻译

- 修复书签窗口拒绝键盘焦点且未转发 Enter 的问题。点击书签展开 / Alt+T 展开后，书签接收焦点，普通 Enter 和小键盘 Enter 均可立即翻译；点击边框也可聚焦。
- 动画尚未结束时按 Enter，会在展开完成后执行一次，不会丢失；长按 Enter 的自动重复不会排队多个请求。展开动作本身仍不翻译。
- 新增全局立即翻译默认 `Ctrl+Alt+Enter`，可在浏览器或其他应用中直接翻译当前范围，待机时会先展开。全局翻译不夺走原应用焦点；普通 Enter 不全局拦截，其他软件正常打字 / 换行。
- “设置 → 快捷键”分别配置展开 / 收起与立即翻译，两项独立注册、检测占用、保存和退出注销。设置输入框中的 Enter 不会触发区域翻译；窗口置顶选项改变后重新注册两项快捷键。
- Windows 原生键盘输入自检覆盖：点击书签后的主键盘 Enter、小键盘 Enter、其他窗口普通 Enter、从待机全局修饰 Enter、设置输入框保护与不夺焦点。不使用真实 API 或用户凭据。

普通 Enter 仅在书签 / 翻译框有焦点时生效；浏览器仍有焦点时请用全局组合键。macOS 全局监听仍需要辅助功能权限，尚未实机验收。

## 0.3.5 明确的翻译触发

- 每次启动默认关闭自动翻译。点击书签 / Alt+T 只展开或收起识别范围，不发送 OCR / 翻译任务。
- 自动关闭时，只有“立即翻译”或 Enter 明确触发区域翻译；移动、缩放、保存模型 / 语言 / API / 外观不会隐式请求。API 页的模型获取与模型测试仍仅由各自按钮显式触发。
- 自动开启后，展开、移动、缩放、设置更新和页面真实变化才允许自动翻译；关闭自动模式会取消待执行 / 未完成的自动任务，不影响明确发起的手动翻译。
- 收起 / 重新展开会使上一轮延迟的手动触发失效，避免旧回调在新展开后突然发送请求。收起时清除待补扫状态。
- 回归测试使用计数 Pipeline 验证非翻译操作请求数为 0、手动翻译只执行一次、自动开关和延迟请求取消；桌面自检显式验证展开后模型服务调用次数不变，再点击手动翻译。

## 0.3.4 源窗口截图与真实任务计数

- Windows 主界面改为直接读取下方应用窗口（PrintWindow），OCR 和画面变化监测使用同一份源窗口画面。译文、书签、光晕不参与源窗口比较；不再仅凭 SetWindowDisplayAffinity 返回成功就假定桌面截图已经排除了自身。
- 主界面取消截图排除标记，屏幕截图可正常显示蓝色边框和译文，不再因截图排除出现黑色边框。原位覆盖与书签动画保留。
- 当源窗口不支持独立截图，或区域跨越窗口 / 屏幕时，使用显式的干净单次截图回退；暂停不可靠的后台画面比较，不使用包含自身遮罩的截图取消译文。已有译文不会因后台定时检查反复隐藏。可用手动翻译、移动范围或在译文上滚动触发更新；不支持的源窗口在诊断中标注兼容模式。
- 画面监测间隔为 350ms，真实滚动仍清除旧译文并在停稳后自动更新。源窗口读取会处理屏幕缩放，限制整窗位图尺寸；跨屏幕区域保留原有合成截图回退。
- 诊断记录使用实际任务序号，从 1 开始，内部画面版本号不再显示为翻译次数。后台画面检查与静止页面跳过不计数，显示当前启动的点击 / 设置与自动尝试数量。
- 默认只展示主要阶段并用秒显示；详细毫秒阶段需勾选展开。取消任务明确表示旧结果未显示，显示捕获方式和取消原因；未执行的显示阶段不再伪装成 0ms 完成。
- 在真实 Chrome 合成页面上验证：桌面因中文遮罩而改变，但源窗口截图不变，译文保持显示，多次后台检查计数为 0。原生慢请求自检另验证真实滚动、自动翻译和源窗口隔离。

Windows `PrintWindow` 对某些受保护内容或不支持打印的 GPU 窗口可能不可用；本版本会走上述兼容回退，诊断中可查看捕获方式。macOS 仍需实机验收。

## 0.3.3 模型勾选、译文稳定性与单次耗时

- 获取列表仅更新“候选模型”。在“勾选 / 管理模型”中勾选后保存，右键菜单只列出已勾选模型；初次升级仅保留当前模型，不把已有 14 项或其他候选列表自动全部启用。支持搜索、手填 ID、仅保留当前，勾选跨搜索保持，当前模型始终可访问。
- 勾选不改变当前使用模型。双击行或“设为当前模型”才改变当前模型；API 设置中的勾选需再点击外层保存，取消不会写入。选择按接口、协议、鉴权方式和 Key 指纹隔离保存在 `enabled-models.json`，没有原始密钥。
- 一级菜单精简为展开 / 收起、立即翻译、自动翻译、选择模型、设置、显示原文、复制译文、翻译耗时与诊断、退出；API、OCR、外观、快捷键和高级开关归入设置。
- 修正忙碌时自动定时器排队强制扫描、旧任务结束时双重调度补扫的路径；外沿光晕不绘入截图矩形任何像素，包括圆角。当前版本结果只在真实画面变化时失效，旧任务不会覆盖新任务。
- 当前请求已有完整流式段落时，后续批次失败不再清空这些译文；可从诊断查看“部分完成”与错误。兼容模型把正确 JSON 数组放在说明或代码围栏中，仍严格校验段落数量与类型。
- 保存模型、语言或连接后，在工作模式下自动重新翻译；待机不被设置保存展开。
- “翻译耗时与诊断”展示最近 20 次实际任务：截图、画面比对、线程排队、摘要、OCR（含缓存标记）、段落缓存、客户端准备、API 等待与生成、首个内容、格式解析、覆盖绘制的 CPU 提交、端到端总耗时。完成、失败、部分完成、取消分别记录，静止画面检查不污染任务历史；支持复制诊断，不包含 Key 或 OCR 正文。
- 已用当前第三方接口翻译合成英文页面验证中文稳定覆盖；本地慢请求自检验证等待时与完成后的显示、模型勾选菜单和真实计时。性能数字为测量结果，首个内容为 API 阶段内的时间点，不重复相加。

自检：`python run.py --experience-self-test <目录>` 使用合成文档和延迟 localhost 接口；`--catalog-self-test` 额外验证勾选保存。建议使用独立 `FLOATTRANSLATE_CONFIG_DIR`。全局快捷键自检采用独立组合键，避免干扰正在运行的主程序。

## 0.3.2 第三方连接与完整模型选择

- API 地址可填写基础地址或完整 `/models`、`/chat/completions`、`/responses`、`/messages` 地址，保存时归一到基础地址，避免重复版本或端点后缀。
- 服务商自动识别依据域名；第三方通用 Key 不会被臆测为某家官方供应商。增加明确的 API 协议（Chat Completions / Responses / Anthropic / Gemini）与鉴权方式（自动 / Bearer / x-api-key / x-goog-api-key）。模型列表与翻译调用共享同一套配置。
- 兼容 `data` / `models` / `items` / 嵌套列表 / 原始数组，以及 `id` / `slug` / `model_id` / `model` / `name` 字段；支持游标和页码等分页，去重保留完整 ID。分页失败或循环时保留成功结果并提示可能不完整，不把它当完整列表。
- “搜索 / 全部模型”支持搜索所有接口返回的模型，无 100 项截断。右键快捷菜单保留前 12 项，同时提供完整搜索入口。下拉箭头始终可见。
- 手动模型 ID 始终可编辑；获取、搜索、刷新和切换连接不会用第一个模型覆盖当前输入。手动别名不必出现在 `/models` 返回列表中。
- 模型缓存按接口、协议、鉴权方式和 Key 指纹隔离，保存到 `model-catalogs.json`，不含原始 Key。重开设置可继续搜索已获取的模型。接口提供端点类型时显示类型，图像生成模型会标明不用于文字翻译。
- “验证并获取模型”只读取模型列表；“测试所选模型（少量额度）”才发起一次显式的小请求（最多 64 个输出 token）。读取列表成功不代表每个模型都支持当前协议或具有调用权限。Responses 模型使用原生 `/responses` 调用。
- 新 API 设置页可滚动，保存按钮保留在底部。原有书签、动画、密钥存储和 OCR 流程保持可用。

模型列表由网关和 Key 权限决定；未返回的模型不能凭空发现，可手动填写平台提供的完整 ID 再测试。Windows 自检使用两页 350 个合成模型验证搜索、选择、保存、缓存和两种调用协议；不会调用真实服务商生成文本。

本次参考以下项目的设计与兼容策略，自行实现 Python / Qt 适配，没有引入这些应用的运行依赖或读取它们的私有配置：
- [CC Switch 模型获取服务](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/model_fetch.rs)：端点归一化、不同模型目录结构、鉴权与端点失败处理。
- [Codex++ 模型目录](https://github.com/aaron5470/codexplusplus/blob/main/crates/codex-plus-core/src/model_catalog.rs)：版本化地址、嵌套目录解析和模型来源状态。
- [Codex++ provider support](https://github.com/yuguorui/codex-plus)：显式协议和鉴权配置。

`python run.py --catalog-self-test <目录>` 可在独立 `FLOATTRANSLATE_CONFIG_DIR` 下运行本地模型目录桌面自检。

## 0.3.1 展开 / 收起缩放修复

修复 Windows 带孔窗口在生成动画快照时被 Qt 重新定位、裁剪，导致只剩角点的问题。现在按完整窗口坐标生成快照，并在动画阶段以矢量重绘缩放边框，避免细线缩小时消失；动画范围覆盖书签锚点，左右展开都不会截断。展开与收起采用 460ms 缓出曲线，可中途反向。新增左右两种位置的快照边框和中间帧像素范围回归验证。

## 0.3.0 侧边书签与外沿呼吸

- 启动进入待机，只显示蓝色书签。单击书签或 `Alt+T` 展开 / 收起；拖动整块书签移动，松开保持原位。
- 工作模式从书签处双向缩放展开、收起；快速切换会从当前动画进度反向播放。右侧书签向左展开，下方空间不足则向上避让，书签不回跳。
- 浅蓝色边界标明识别范围，不显示“工作中”。远离书签的下角蓝色触点用于自由缩放，向左展开时触点在左下角。
- 实际 OCR / API 请求运行期间，边框外蓝色柔光缓慢呼吸；完成、暂停或收起即停止。文字和边框保持稳定，没有人为延长翻译等待时间。
- 展开后立即翻译，默认开启自动模式；静止画面跳过重复工作，滚动先清除旧译文。收起时停止扫描并丢弃旧任务结果。
- 右键书签、边框或托盘打开全部设置，包括“展开 / 收起快捷键”。快捷键写入原配置文件，Windows 支持全局注册并检测占用；macOS 全局按键监听需要“系统设置 → 隐私与安全性 → 辅助功能”授权，未授权时可点击书签。
- 保留现有 API Key 钥匙串和原位覆盖流程。Windows 仍采用原生带孔遮罩以排除自身截图；外沿柔光为独立透明、鼠标穿透图层，框内区域不填色。
- 本版本在 Windows 实机验证。macOS 代码保留 Apple Vision / Quartz 路径，但尚无 Mac 实机验收，需在 Mac 上运行 `python build.py` 生成 `.app`。

### 快速使用

退出旧版后启动 `FloatTranslateNext-0.3.0.exe`，先在书签上右键配置 API 与模型，再单击书签展开。原配置及密钥会继续读取。此版本不会自动调用未配置的供应商，也不会为了演示动画增加 API 延迟。

### 验证

`python -m pytest tests -q --basetemp=<独立测试目录>` 运行回归测试。真实 Windows 桌面可运行 `python run.py --bookmark-self-test <测试输出目录>`，使用合成英文文档、系统 OCR 和 localhost 模型服务验证，不调用真实供应商；建议设置独立的 `FLOATTRANSLATE_CONFIG_DIR`。旧的 `--self-test` 保留用于底层覆盖组件回归。

## 0.2.3 静止画面与操作热区

- 自动模式遇到未变化的画面时，不再启动 OCR / 翻译工作线程或边框扫描动画；相同的原生窗口遮罩也不会重复设置，避免定期刷新闪一下。
- 画面比较过滤细小光标和低幅度渲染噪声，仍保留滚动与明显文字变化检测。手动“立即翻译”可随时重新检查。
- 顶部整条 28px 区域可拖动，内侧边框和译文区域也可移动窗口；四个角的缩放热区扩大到 24px。最外侧 6px 边缘用于单方向缩放，边框蓝线保持细线风格。
- 本机桌面自检在 4.7 秒内跨过多个自动扫描周期，确认工作线程启动次数和窗口遮罩重设次数均为 0；同时验证顶部远离中心的区域仍可拖动。

## 0.2.2 滚动、闪烁与速度

- Windows 改用有真实空洞的窗口区域，支持系统截图排除，正常路径不再通过隐藏 / 显示窗口截图。译文使用不透明白色底色，边框保持流光效果。系统截图也会排除识别框。
- 滚轮经过译文时，先清除旧译文，再转发给下方页面；在框内透明区域滚动可直接操作原页面。Windows 后台画面监测每 180 ms 检查一次变化，即使自动翻译关闭，也会清理已失效的遮罩。
- 自动翻译在页面停稳约 400 ms 后更新；旧画面的流式请求会被取消或丢弃结果，避免滚动后又盖回旧文字。
- OpenAI 兼容接口支持流式按段显示，不必等待整个画面全部翻完。明确拒绝流式的网关可自动回退普通请求。
- 缓存改为按段落复用，滚动时重复段落不会再发请求。右键“本次识别与接口耗时”可查看截图、OCR、接口生成及缓存命中。
- “优先速度”默认开启：对 DeepSeek 官方域名使用 `thinking: {type: disabled}`，适配 `deepseek-flash` 等支持该开关的模型。未知第三方网关不接收 DeepSeek 专有字段，其思考控制需按服务商协议适配。参见 [DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。真实响应时间仍受模型、网络和供应商负载影响。
- Windows 中拖动顶部中间短线或译文区域移动；四边、四角仍可自由缩放。右键边框、译文或托盘打开菜单。透明空白处的鼠标操作直接交给底下应用。

macOS 仍使用原有透明窗口与截图回退，尚未完成同等级的无闪烁实机验收。

## 0.2.1 修复

修复保存、取消或关闭设置后程序自动退出的问题：透明识别框是 Qt 工具窗口，不参与“最后一个主窗口关闭”的计数。现在禁用 Qt 隐式退出，由右键菜单的“退出”明确结束程序；关闭设置后恢复识别框的可见性。配置和凭据存储位置保持不变。

新增真实应用事件循环的回归测试，覆盖 API / OCR / 外观设置的保存、取消、关闭、Esc，以及切换始终置顶。源码测试共 60 项；桌面自检另执行 13 条窗口生命周期检查。

## 界面与操作

主界面只有透明识别框，采用蓝紫细线与流光动效。没有标题栏、侧栏或独立译文面板。译文在 OCR 检测到的原文段落位置，以白色底块覆盖显示。

- 拖四条边、四个角：自由缩放，最低 140 × 90 逻辑像素，不锁定宽高比。
- Windows 拖顶部整条 28px 抓握带、内侧边框或译文区域：移动位置；macOS 可拖框内区域。四个角的 24px 热区和最外侧边缘可缩放。移动或缩放会清除旧译文，防止错位。
- 右键边框、译文或托盘：立即翻译、自动翻译、选择模型、API 与供应商、OCR 与语言、边框与动效、鼠标穿透、暂停、复制译文、耗时、退出。
- `Enter`：立即翻译；`Esc`：清除覆盖层。
- 鼠标穿透开启后，通过右键系统托盘 / macOS 菜单栏图标的“显示并恢复交互”关闭穿透。系统托盘不可用时，穿透选项禁用，避免无法操作。
- 框的位置和大小在正常退出后保存，下次启动恢复；自动翻译默认关闭。

“边框与动效”可调线宽、译文字号上限，并可关闭动画。Windows 无闪烁模式固定使用不透明底色；macOS 可调底色透明度。文字密集或译文过长时会缩小字号，极小区域仍可能被裁切，可通过右键复制全部译文。

## 本地运行

需要 Python 3.11+。建议使用 Python 3.13；Windows 10 2004+ / Windows 11 或 macOS 13+。

```sh
python -m venv .venv
# Windows PowerShell
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe run.py
```

macOS：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Windows OCR 需要系统安装对应语言的 OCR 组件。macOS 使用 Apple Vision，无需 Windows OCR 依赖。首次截图需要在系统设置的“隐私与安全性 → 屏幕与系统音频录制”（系统版本不同名称可能略有区别）授权当前应用；源码运行时可能显示 Python 或终端。授权后重启应用。

## API 配置

右键 → **API 与供应商**：

1. 选择服务商，或选择自动识别并填写 API 基础地址。
2. 填写 Key，点击“验证并获取模型”。
3. 选择支持文本对话的模型，保存。部分接口不开放 `/models`，可手动填写模型 ID。

内置 OpenAI、DeepSeek、Claude、Gemini、硅基流动、OpenRouter、Moonshot、百炼、Groq、Ollama，以及自定义 OpenAI / Anthropic / Gemini 协议。大多数第三方网关应选择“自定义 · OpenAI 兼容”，填写类似 `https://example.com/v1` 的基础地址，不要填写完整的 `/chat/completions` 地址。

自动识别根据精确域名和少量有明显特征的 Key 前缀进行。普通 `sk-` Key 无法唯一确定服务商，必须提供地址。未知域名默认使用 OpenAI 兼容协议；Anthropic/Gemini 网关需手动指定协议。不会拿 Key 到多个平台试探。

Key 存入 Windows 凭据管理器 / macOS 钥匙串，配置 JSON 不保存 Key。系统凭据服务不可用时，仅保留到本次退出并给出提示。官方接口也可使用对应的 `OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY` / `GEMINI_API_KEY`。本机 Ollama 可不填 Key。公开接口要求 HTTPS。

## 架构与性能

- `frame.py`：无边框窗口（Windows 为区域裁剪，macOS 为透明窗口），8 方向缩放，右键菜单，后台画面失效检查，Qt 信号接收流式结果。
- `capture.py`：按屏幕逻辑坐标分段截图，统一 DPR 后合成；支持负坐标屏幕与 Retina 坐标映射。暂存截图最多约 1200 万像素。
- `ocr.py`：Windows WinRT OCR / macOS Apple Vision 条件导入，返回文字及边界框；Windows 缩图后还原坐标，macOS 将左下角归一化坐标转换为左上角像素坐标。
- `layout.py`：按位置、行高和间距合并相邻行，避免将不同列简单拼在一起。
- `pipeline.py`：串行 OCR / 翻译工作线程，16 项识别缓存、256 项逐段 LRU 翻译缓存、HTTP 连接复用。每批最多 12 段 / 约 6000 字符，流式返回完成的段落，避免逐行请求。
- 请求失败不写入成功缓存；自动模式失败后逐步退避。窗口或配置改变后，过期任务不能覆盖新位置。
- 只有识别工作时运行 30 FPS 边框动画；静止时不持续重绘。Windows 新译文直接覆盖，减少闪动；macOS 保留可关闭的淡入。

Windows 使用不依赖逐像素透明的区域窗口，支持排除自身的系统截图功能。极少数系统不支持排除时，以及目前的 macOS 路径，仍会短暂隐藏覆盖窗口后截图再恢复。快速画面监测仅在截图排除可用时运行，避免反复触发该回退。macOS 后续可进一步迁移到带窗口排除的 ScreenCaptureKit。

## 打包

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python build.py
```

Windows 输出 `dist/FloatTranslateNext.exe`；macOS 输出 `dist/FloatTranslateNext.app`。必须在对应系统上打包，Windows 不能直接产出可验证的 macOS 应用。Mac 的 CPU 架构与构建机器一致；Intel / Apple Silicon 应分别构建测试。

`.github/workflows/build.yml` 提供手动 Windows / macOS 构建。将本目录作为仓库根目录上传后，可在 Actions 触发。工作流仅构建和上传 artifact，不发布 Release。macOS 产物为本地 ad-hoc 签名，公开发行需要开发者自己的 Apple 签名与公证。

## 验证

```sh
python -m pytest -q
# 在有桌面的目标系统上进行真实 OCR、截图与覆盖测试；需要屏幕权限
python run.py --self-test /absolute/path/to/test-output
```

自检只展示人工构造的英文文档，真实调用本机 OCR，并连接 localhost 的模型模拟接口；不使用个人 Key、不调用外部供应商。输出截图、坐标和 JSON 报告。单元测试涵盖 8 方向缩放、坐标、缓存、错误重试、供应商协议、分页、配置持久化及设置界面。

当前 Windows 已通过真实 OCR 和覆盖流程验证；macOS 代码与构建流程已提供，但仍须在真实 Mac 上完成屏幕权限、Retina、多显示器、拖动和 OCR 的验收。复杂排版、旋转文字和极长译文的覆盖仍需要进一步调优。
